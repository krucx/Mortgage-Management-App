Install Mortgage Management

The app runs on the Lender's own laptop, and nowhere else. On Windows it is a double-click: download Setup, answer three questions, and open the shortcut it puts on the Desktop. This page takes you through it for your own computer, and then through everything after: starting it, updating it, Backups, bringing a Backup back, and removing it.

Download Setup.bat

For Windows 10 and 11. It always installs the newest release, so this one file stays good: keep it to update later. Also on GitHub.

Newest release: 2.0.0 Takes: 5–15 minutes Needs: an internet connection while installing Opens at: http://localhost:8080

Your computer

Pick yours: every step below changes to match. Setup checks for Docker by itself, so a wrong guess here does no harm.

Which computer is the app going on?
Is Docker Desktop installed on it?
Windows, without Docker. Setup installs what the app needs (uv, which brings Python) and the app runs on the PC itself, from a window that stays open while you use it.
Windows, with Docker Desktop. Setup downloads the published app into Docker. It runs in the background, and Backups can have a password.
Mac or Linux, with Docker Desktop. There is no double-click setup here: a few commands in Terminal, once.
With or without Docker: which is better?
Without DockerWith Docker Desktop
Install firstNothing: Setup installs uv itselfDocker Desktop (it may ask to restart the PC)
While you use itIts window stays open; closing it stops the appRuns in the background, and starts again with Docker
Backup zipsPlain zips, no password (Windows has nothing built in to make them)Can have a password, asked for during Setup
Best forMost Lenders: the least to install and look afterBackups kept in a shared or synced folder, where a password matters

You can change later: install Docker Desktop and run Setup again, and it moves the app into Docker, keeping the data.

Start and use it

Every day after the install.

Only on this laptopThe app answers at localhost only: no one else on the network, or the internet, can reach it.
Nothing is kept in the browserFigures always come fresh from the app's server, so clearing the browser loses nothing.
A different portIf something else already uses 8080, set APP_PORT in app\.env (for example to 8090) and start it again.
4

Update to a new release

What changed in each release is in the changelog.

In the app's folder, in Terminal:

git pull
docker compose pull
docker compose up -d

To go back to an earlier release, set APP_VERSION in .env (for example 1.2.0) and run the last two commands. If a newer release updated the database, restore the Backup taken before that update.

A Backup comes firstWhen a release updates the database, the app takes a Backup marked -before-update before it does. If that Backup fails, the app doesn't start, so the data is never changed without one.
Or from the app itselfWhen a newer release is out, the app shows a banner with what's new. On Windows, Install now runs Setup for it (Windows asks once whether to open it), and the app reloads by itself once the new version runs. Later hides it until the next release.
Nothing to download when it's currentSetup compares the version you have with the newest first: if you have it, it downloads nothing and just starts the app.
The version before is keptEach version has its own folder in MortgageManagement\versions, and app points at the one that runs. The one before stays there; older ones are removed after an update.
Nothing to download each timeSetup.bat always fetches the newest release, so the same file works for every update.
5

Backups, and bringing one back

The whole book, database and photos, in one zip.

Weekly, by itselfOn the first use of the day one falls due, the app writes mortgage-backup-<date>-<time>.zip to the Backup folder, and keeps the last few (4 by default).
Any time, by handSettings shows the last Backup and has a Back up now button. Use it before anything risky.
Off the laptopA Backup folder in Google Drive, OneDrive or iCloud means a lost laptop doesn't lose the book. To move it later, change BACKUP_DIR in app\.env, then start the app again.
Moving the dataStop the app, move mortgage.db and the photos folder together, then change DATA_DIR in app\.env to that folder before starting the app again.
To bring a Backup back
Moving to a new laptopInstall it on the new one, then bring back the latest Backup as above. On the old one, remove it: that keeps the latest Backup in Documents first.

In this orderIt stops the app, keeps the latest Backup in Documents, and only then deletes: the Docker images, the Desktop shortcut, the data, and the MortgageManagement folder.

If something goes wrong

Setup and the shortcut say in red what stopped them. The most common, and what to do:

The app says “The app's server isn't running”

The screens opened, but the server behind them is stopped: usually the browser or installed app was opened on its own.

  • In the installed app, click Start Mortgage Management. Or open the Mortgage Management shortcut on the Desktop, then reload the page.
  • If that doesn't help, check Docker Desktop is running (its whale in the taskbar's corner).
  • Start Docker Desktop; the app starts with it. If not, run docker compose up -d in its folder.
Setup says “Offline: starting the version you have”

GitHub couldn't be reached, so Setup started the version already installed instead of updating it. Run Setup again once the laptop is online to update. The very first setup always needs internet.

“Start Mortgage Management” waits, then says it hasn't started

Open the Mortgage Management shortcut on the Desktop: its window says in red what stopped the app. If the button does nothing at all, run Setup once more, which registers the link it uses.

Windows won't let Setup.bat run

On Windows protected your PC, click More info, then Run anyway. If there is no Run anyway, right-click Setup.bat → Properties, tick Unblock at the bottom, OK, and double-click it again.

“winget is missing”

Setup uses winget, Windows' own installer, to install Node.js, which it needs only to set up code that isn't released yet. Install App Installer from the Microsoft Store, then run Setup again.

“Docker Desktop did not start” or “Docker is installed but not running”

Open Docker Desktop yourself and wait until it says Engine running (the first start after installing it can ask to finish setting up, or to restart the PC). Then run Setup, or the shortcut, again.

Setup stopped part-way (a lost connection, a closed window)

Run it again. It picks up where it can, and never touches the data or Backups.

I closed the app's window by mistake

Nothing is lost: everything saved is in the data folder. Open the shortcut again.

Something else uses port 8080

Set APP_PORT to another number (for example 8090) in C:\Users\you\MortgageManagement\app\.env.env, start the app again, and open http://localhost:8090.

The Backup password is lost

Backups made with it can't be opened, by anyone. The book itself is fine: set a new BACKUP_PASSWORD in app\.env, start the app again, and take a Backup with Back up now, so there is one you can open.

Still stuck

Open an issue on GitHub with the red message from the window, or a photo of it.
