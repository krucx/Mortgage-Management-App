Check yourself

Questions mixed from all five lessons, then a change in the real repo: remove the check that stops a Payment paying more than is owed, and predict which tests notice.

Quiz: which layer, which file?

1. The Preview's "Owed today" figures are wrong but the save is right. Can that happen?

preview_payment calls record_payment inside _preview and rolls back. One set of rules, so they can't disagree (ADR 0007). A wrong Preview means a wrong save.

2. Which file holds the route POST /api/payments?

Trap #1: a Payment's write is in payments/recording.py. payments.py reads Payments; receipts.py builds Receipts.

3. A trace: the chain owes ₹80,000 Principal, ₹2,800 unpaid interest and ₹533 Interest to Date. A Payment of ₹3,000 to it pays how much Principal?

Unpaid interest first (₹2,800), then the Interest to Date (the remaining ₹200 of its ₹533), then Principal: nothing left. It would take more than ₹3,333 to reach the Principal.

4. Where does the Network tab's POST /api/payments/preview body come from?

The form builds proposed (a PaymentIn) once; the Preview and the save both send it. That's why the Preview is of exactly what would be saved.

5. After a save, which function makes the Mortgages list and Dashboard stale?

useLedgerChange calls ledgerChanged after every Ledger-changing save. check_replays is a backend check, and usePreview only asks for Previews.

6. A trace: a back-dated Payment is recorded before an older-saved one. What happens to the older one's allocation row?

The row holds only the amount, which doesn't change. How it divides between interest and Principal is replayed each time it's read, so it can change: Payment 34's chain line went from ₹1,600 / ₹0 to ₹1,333 / ₹267.

7. Which request's answer carries the WhatsApp message text?

The Receipt's text field is the message, worded from the Receipt template. The save and load_payment return the Payment, without any message.

8. Why does the Receipt say "Pair of bangles" and not "2026-Meera-PairBangles"?

It's a rule, written into the glossary's definition of Receipt: name each Mortgage by its description, never its Mortgage Name. load_receipt uses description; the template can't change that.

Recap

  • A Payment makes four requests: the list as of its date, the Preview, the save, and the Receipt. Lesson 1
  • The form builds proposed, the exact body saving would send; the backend previews it by running the real save and rolling back. Lesson 2
  • post_payment in payments/recording.py runs record_payment in one transaction: refuse, write, check, record. Payment writes are not in payments/. Lesson 3
  • Only amounts are stored; how a Payment divides between interest and Principal, and what's still owed, are replayed every time. Lesson 4
  • ledgerChanged marks every money cache stale; the Receipt is replayed by the backend; the Lender sends it on WhatsApp themselves. Lesson 5
