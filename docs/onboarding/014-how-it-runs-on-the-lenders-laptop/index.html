Chapter 014

How it runs on the Lender's laptop

The problem this chapter solves

Everything until now ran on your machine, with you watching. The real app runs on one laptop you'll never see, owned by a Lender who isn't technical. It has to install from a double-click, start from an icon, update itself without losing a rupee of history, and keep the records in a folder that survives all of that. It runs two ways: in Docker where Docker works, and as one plain Python process on Windows PCs where it doesn't.

Get this wrong and the failures are the worst kind: silent and far away. An update that dies halfway leaves the Lender with no app on a busy morning. A screen that caches too long hides an update for a year. And for you, the developer, one command typed without two variables runs unreleased code on real records and migrates them for good.

This chapter is about running and debugging, not reading every line. You'll run the app in Docker and without it, side by side, on a copy of the sample book. For Windows, you'll read only the functions that decide things, and run their Pester tests in Docker. No Windows PC needed.

What you'll be able to do

  • Run your own code in Docker on scratch data, and debug it with ps, logs and exec.
  • Serve the built screens from the backend, and check with curl that both modes cache the same way.
  • Explain what Setup does on a Windows PC, and run and read the scripts' Pester tests.
  • Explain how an update switches versions, and what it can and can't undo.
  • Explain how the installed app starts and updates the app through mortgage-management://, and why that link is narrow.

Before you start

  • The sample book, served. Chapter 002, lesson 4: $BOOK built by book.py and served by serve.py on 8765, the clock held on 19 Oct 2026. Lesson 1 copies its data folder, so it can be a book you've changed in earlier chapters; lesson 2 compares the two. If you'd rather start clean, rebuild it into a fresh $BOOK.
  • Docker, your own code: the warning. Chapter 002, lesson 5 gave the dev compose command with -p mortgage-dev and APP_PORT=8081. This chapter explains it.
  • The composition root and migrations. Chapter 010, lessons 1, 2 and 5: create_app and its arguments, where today comes from, and why every start migrates the database after a -before-update Backup (trap #9).
  • The installed app. Chapter 012, lesson 6: the service worker, StartGate and UpdateBanner.
  • Pester. Chapter 013, lesson 1: how to run it in the mm-pester image.

You need Docker Desktop running, plus uv and Node as before. Lessons 1 and 2 start containers and servers; lessons 3–5 only read code and run Pester. Nothing in this chapter changes your served book or the repo, except the check-yourself's one-line breaks, which you undo.

Plans that changed. This chapter was planned (issue #201) when Docker ran nginx in front of the backend. Since commit 3137302 (ADR 0013) it's one image and one service, app, and the backend serves the screens in both modes. So frontend/Dockerfile, frontend/nginx.conf and the gap filed as #117 are gone; a stopped backend in Docker refuses the connection instead of answering 502; and Pester has 65 tests, not 61. The lessons teach the code as it is, and say where the plan differed.

The map

Notice that both paths meet at screens.py: whichever way the app runs, one Python process answers the API and the screens on one port. That's why lesson 2 can compare the two modes with curl and find them identical.

Lessons

  1. The app in DockerOne image, one service: your build on a copy of the book, on 8081. Debug with ps, logs, exec; watch Compose refuse, or quietly take .env's folders, without the two variables.
  2. Without Docker: the backend serves the screensscreens.py's twenty lines, serve.py beside Docker, the same headers from both; what test_screens.py pins; a stopped backend.
  3. Setup on WindowsCI's windows job as the story of one install: the code fetched, its own install run, the .env, uv sync, run.ps1. 65 Pester tests, run in Docker. ASCII only.
  4. Each version in its own folderArjun's Tuesday update: the new version beside the old, the junction moved last, the old one started again on failure, and the Backup Setup names but won't restore.
  5. The mortgage-management:// linkMeera's payment day: Start on the installed app runs link.ps1, which takes two actions and nothing else, gated twice.
  6. Check yourselfEight questions; then loosen the link's regex and see which one of 65 tests notices, and break screens.py's caching rule.

Written against commit 36d403e. Every command output, header, count and failure came from scripts/run_throughs.sh, on 6 Nov 2026. It builds a fresh sample book in a temp folder, runs the dev image on a copy (under its own image name, so an existing :dev is never retagged) beside serve.py, runs Pester, and makes the check-yourself breaks on copies of windows/ and backend/, so your clone is never touched. Run it from the repo root with sh docs/onboarding/014-how-it-runs-on-the-lenders-laptop/scripts/run_throughs.sh. Docker's figures follow the real today, so yours will differ by the days since.

Anything unclear? Ask an agent in this repo to explain it: a Compose error, a header, a Pester test, or what a script does on a PC you don't have. If something here looks wrong, open an issue (see Documentation/agents/issue-tracker.md).
