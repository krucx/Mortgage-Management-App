Check yourself: Testing

Questions from all five lessons, mixed up. Then make seed.py record every Payment on the tests' today, and see which tests the app itself refuses to set up.

Quiz

1. What date is "today" in a test that uses the client fixture, and where is it set?

client builds the app with create_app(database_url, today=lambda: TODAY), and TODAY = date(2026, 4, 20) at line 11. 19 Oct 2026 is the sample book's day, which no test uses. Moving TODAY a day fails 48 tests, which is why it's fixed (lesson 3, trap #17).

2. Which check that guards the frontend does CI not run, and what does it catch?

test.yml's frontend job runs npm run typecheck and npm test, never npm run lint. A fetch no test reaches passes CI; only oxlint's no-restricted-globals rule catches it (lesson 1, trap #11).

3. Trace it. A client test makes Ramesh with person(client) and his chain with lend(client, ramesh), all defaults. What does the chain owe on the tests' today?

lend's defaults are ₹1,00,000 from 14 Jan on SIMPLE_3. On 20 Apr the Ledger has ₹3,000 on each of 14 Feb, 14 Mar and 14 Apr, and ₹3,000 of Interest to Date for the month from 14 Apr, charged in full: ₹1,12,000 (scripts/figures.py). test_seed.py's comment says ₹1,09,000; the app says otherwise (lessons 2 and 3).

4. You're adding three things: a new rounding rule in the Ledger, a new refusal of a Payment, and a new route listing Voided Payments. Which layers?

An engine figure is pure: compute_ledger in test_ledger.py, no database. The Lender meets a refusal as a status and a message from a route, and a new route is best tested as the frontend calls it: both client with api_seed.py. conn is for functions with no route, or histories over many dates (lesson 3).

5. Why is the HTTP helper file called api_seed.py and not http.py?

backend/tests/ has no __init__.py, so pytest puts it at the front of sys.path. FastAPI's own import http would load the test file, and every test fails at conftest with a circular-import error in FastAPI (lesson 2, trap #18).

6. A page test routes only GET /api/mortgages/7. What does fakeServer answer the page's other requests, and why does it matter?

Unrouted is 404 {"detail": "Not Found"}, as the backend says for an unknown route. Answering 200 {} instead fails 17 tests: panels trust their types and crash on {} (notes.map is not a function). The fake answers only what the real backend could (lesson 4).

7. Trace it. In a client test, Ramesh's default chain is paid ₹12,000 on 20 Apr: pay(client, ramesh, {chain["id"]: 12_000 * RUPEE}, on="2026-04-20"). Is the chain on the Call List afterwards?

₹12,000 pays the ₹9,000 of unpaid interest and the ₹3,000 Interest to Date, leaving the Principal, ₹1,00,000, and no Months Unpaid; the Call List is empty (scripts/figures.py). Its Accrual Date is the 14th. test_call_list.py's test_paying_the_interest_takes_a_mortgage_off_the_list pays ₹9,000 and gets the same answer (lessons 2 and 5).

8. How do you know a line is pinned by a test?

Running a line isn't pinning it: the Loan-to-Value line ran in every Call List test, and >= still passed all 708. Only a failure on the broken line proves a test cares what it says (lesson 5).

Hands-on: seed every Payment on the tests' today

seed.py passes each change its own date as the change's today (lesson 3). Here you make it pass one date instead, the tests' own today, and see what the app refuses. Work in backend/.

  1. Run the tests as they are: 
    uv run pytest -q
    709 passed (at the commit on the overview).
  2. Open tests/seed.py. In add_payment, line 110 passes the Payment's date as the change's today: 
            paid_on,
        _at(paid_on),
    Change the first of those two lines to 
            date(2026, 4, 20),
    so every seeded Payment is recorded on 20 Apr 2026, the tests' today, whatever day it was paid.
  3. Predict before you run anything: which tests fail, and why? Think about which tests seed with seed.py at all (they're conn tests), and which of those seed a Payment dated after 20 Apr.

Run uv run pytest -q again.

They fail while seeding, before any assertion, with the app's own refusal:

Recap

  • CI (.github/workflows/test.yml) runs uv run mypy src and uv run pytest in backend/, npm run typecheck (tsc -b) and npm test (vitest run) in frontend/, and the image, pages and windows jobs; the release runs it first. mypy reads src only; tsc reads the tests too. CI never runs npm run lint, the oxlint rule that bans fetch. -k and -t filter by name; a path runs one file. Pester runs locally in a Debian arm64 image with PowerShell unpacked (lesson 1).
  • conftest.py gives each test a new SQLite file in tmp_path, an app built on it with today fixed at 20 Apr 2026 (client), or a bare connection (conn). api_seed.py's person, lend and pay send the frontend's requests and fail at once, with the backend's reason, if one is refused. Amounts are paise. Test names are sentences in glossary words. Never name a file in tests/ after a standard-library module (lesson 2).
  • Three layers: pure (compute_ledger, no database, the right place for figures), conn with seed.py (functions with no route, histories over many dates), client with api_seed.py (routes and refusals). seed.py goes through the change functions, each change on its own date at 10:00, so an impossible seed is refused and History is written (lesson 3).
  • showPage draws a page inside the real server state (retry: false) and a MemoryRouter, makes fetch throw, and shows "Now at …" for anywhere it wasn't given a page. fakeServer answers by METHOD /path, records every request, and answers 404 to anything unrouted, as the backend would. The shared mortgage is Asha Rao's, typed, with coming dates in 2099. setup.ts gives jsdom the dialog methods it lacks (lesson 4).
  • A line is pinned when breaking it makes a test fail. Break it, run, look; if nothing fails, write the test, see it fail on the broken line, then pass on the real one. A boundary needs a test on each side; a check every caller repeats needs a test below the callers (lesson 5).
