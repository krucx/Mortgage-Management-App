Check yourself: People and Collateral

Questions from all five lessons, mixed up. All of them are on a fresh sample book on 19 Oct 2026, before any of this chapter's saves. Then one small break in the real code, which shows exactly where the Primary Number rule lives.

Quiz

1. What does GET /api/people/by-phone?phone=9810099999 answer?

9810099999 is Meera's and Sunita's contact number 2, and owner_of only looks at customer.phone_1 and standalone_referrer.phone. A contact number 2 identifies nobody (ADR 0005). It does show up in search and in shares_phone_with. (Lesson 1.)

2. A new Customer, Zara, is typed with a "new" Referrer whose phone is 9810099999. What is written?

Follow question 1: owner_of finds nobody, so _referrer_columns inserts Standalone Referrer 2 on 9810099999 and links Zara to it (from scripts/run_throughs.py, section 99). That number is now someone's Primary Number. (Lessons 1 and 2.)

3. What is Arjun's gold chain's (Mortgage 8: 12 g net, 22K, owing ₹46,830) Collateral Value and Loan-to-Value?

12 g × ₹13,536 (the 22K rate) = ₹1,62,432; 46,830 ÷ 1,62,432 = 0.2883. The first divides the wrong way round; the third uses the 24K rate, ₹14,766. (Lesson 5.)

4. The Lender edits Arjun and sets his contact number 1 to Ravi Verma's, 9811122233. What happens?

Promotion happens only for a new Customer (customer_id is None in _checked). On an edit, any number that's someone else's Primary Number is refused with 409 by _number_taken. (Lessons 1 and 2.)

5. What does POST /api/customers/7/delete-preview (Sunita) answer?

Sunita has the mangalsutra (Mortgage 9). remove_customer refuses any Customer with a mortgage row, Active or closed. A Customer Preview never has a body: it's 204 or the refusal. (Lesson 3.)

6. A script edits Meera with a PUT whose body has no pan field. What happens to her PAN?

pan defaults to None on CustomerIn, and edit_customer writes every field. History gets edited · pan · ABCPS1234K → (empty). A PUT is the whole Customer. (Lesson 3.)

7. An upload of Meera's PAN photo is a valid JPEG, but the change raises an error inside the transaction. What's in data/photos afterwards?

photo_change wrote the new file before the transaction, then deleted it in its except branch. The old file is removed only after a commit, which never came. (Lesson 4; test_photo_lifecycle.py::test_a_change_that_fails_after_writing_leaves_no_new_file.)

8. The Lender tries to set Lakshmi's necklace (Mortgage 4, Redeemed on 16 Oct) to ₹4,50,000 by hand. What answers?

set_collateral calls _refuse_unless_active first. The value is fine; the Mortgage isn't Active, so the jewellery isn't held any more. (Lesson 5.)

Recap

  • A person is identified by their Primary Number: a Customer's contact number 1, a Standalone Referrer's phone, always cleaned to 10 digits by normalise_phone. Each table is unique on its own; across them, only owner_of in _checked stops a clash (409). Names identify nobody; contact number 2 only warns (lesson 1, ADR 0005, trap #19).
  • A Referrer choice is an existing Customer, an existing Standalone Referrer, or "new". A "new" one whose number is known links to that person; only an unknown number inserts a row. At most one referrer column is set. A new Customer on a Standalone Referrer's number promotes them: referrals move over, the row is deleted, and History records only the new Customer. Nobody is their own Referrer (lesson 2).
  • Customer changes refuse, write, then record History, in customer_changes.py. Their Previews run the same function, roll back, and answer 204 with no body. A PUT is the whole Customer. History keeps the Referrer by name. Only the last 4 Aadhaar digits ever pass parsing; a PAN is unique. A Customer with any Mortgage can't be deleted (lesson 3).
  • Every photo change goes through photo_change: the new file is written before the transaction and removed if it fails; replaced files are removed only after the commit. Files are upright JPEGs at most 1,600 px, with uuid names that read_photo checks. ID Photos are only on the Customer's page; History never names a file (lesson 4).
  • Collateral Value is net weight × the Gold Rate for its purity, rounded half-up to the paisa, or a value set by hand (only while Active). Without a rate there's none. Loan-to-Value is Outstanding ÷ Collateral Value, a float that can pass 100%. Only rates and the hand value are stored; a rate's date moves only when it changes (lesson 5).

Keep the routes sheet open when you work on people or collateral: it now lists every Customer, photo and Gold Rate route with its Preview and refusals. The traps sheet marks #19 as this chapter's, and the glossary now has the Primary Number, Aadhaar Number, PAN and ID Photos.
