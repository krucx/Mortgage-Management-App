Chapter 008 · Lesson 5

Gold Rates, Collateral Value and Loan-to-Value

What is Arjun's ruby ring worth today, and is it still worth more than he owes? This lesson works both out by hand, then shows the 40 lines of code that do the same, and the one value the Lender can override.

By the end you can hand-work any Mortgage's Collateral Value and Loan-to-Value.

The problem

The Lender lends against gold. If a Customer never comes back, the gold is all the Lender has. So the Lender wants to know, for every Mortgage, two things: what the jewellery would fetch now, and how much of that is already owed.

Gold's price moves every day, and the price depends on purity. Pure gold is 24 karat; most Indian jewellery is 22K (22 parts gold in 24); cheaper pieces are 18K or 14K. And a piece's weight includes stones and solder that aren't gold: its net weight is the gold alone.

The obvious design is to store each Mortgage's value when it's lent. It goes stale at once: a value stored in June says nothing about October's gold price, and nobody is going to re-type a hundred values every time the price moves.

The idea

The Lender keeps one Gold Rate per purity, five in all, and updates them when the price moves. A Mortgage's Collateral Value is computed whenever it's asked for: net weight × the Gold Rate for its purity. If a piece is worth more or less than its gold (an antique, a big stone), the Lender can set its value by hand instead. Its Loan-to-Value is Outstanding ÷ Collateral Value.

It's the same rule as the Ledger (ADR 0001, trap #4): store the facts (rates, weights, a value set by hand), work out the rest when asked. Change one Gold Rate and every Mortgage of that purity is revalued at once.

The flow

Notice collateral_of needs the Outstanding passed in. It does no replay itself; each caller already has one.

The code

1. Five purities, five stored rates

Literal[24, 22, 20, 18, 14] means the field may hold only those five numbers; a request with 23K is a 422. Each rate is stored as two rows in the config key–value table, gold_rate_22 (paise per gram) and gold_rate_22_updated_on. ConfigGroup reads and writes such a group of settings as one Pydantic model; chapter 010, lesson 3 covers it. A fresh database has no rows, so every rate starts as None.

2. The valuation: collateral_of

  1. A value set by hand replaces the Gold Rate entirely; weight and purity aren't looked at.
  2. No Gold Rate for this purity means no Collateral Value and so no Loan-to-Value. The API shows "collateral": null.
  3. Weights are in milligrams and rates in paise per gram (trap #6, owned by chapter 004), so the exact value is mg × rate ÷ 1000 paise, which can have a fraction. // is integer division, which rounds down. Doubling everything and adding 1000 before dividing by 2000 is the same as adding ½ before rounding down: rounding half-up, with no floating point.
  4. Loan-to-Value is the one float. It's a ratio for display and comparison, never money.

3. Setting the rates: update_gold_rates

The Settings page sends every rate that's filled in, changed or not. Only the ones that differ are written, so each rate's updated_on says when that price last moved, not when someone last pressed Save. GoldRateIn (line 24) refuses a rate that isn't above 0. Gold Rates aren't recorded in History: they're settings, not changes to a Customer, Mortgage or Payment.

4. A value set by hand: set_collateral

It lives in lending/changes.py because it changes a mortgage row, with the same refuse → write → History shape (chapter 006). It has no check_replays: a Collateral Value doesn't touch the Ledger. The route PUT /mortgages/{id}/collateral (line 1050) takes {"value": paise} or {"value": null}; its body model CollateralIn (line 1046) already refuses 0, so line 525 is a second guard for other callers. Its Preview, POST /mortgages/{id}/collateral-preview, shows the value before and after and whether the Mortgage would be on the Call List.

5. Who asks

The same call appears in load_mortgage (lending/mortgages.py, line 238) for the Mortgage page, in the Dashboard (lending/dashboard.py, lines 223–227) and in the Projection (lending/projections.py, line 91). The Call List puts an Active Mortgage on the list when its Loan-to-Value is above a threshold, 85% in the sample book (loan_to_value_too_high; chapter 009, lesson 1). The Dashboard adds up the Collateral Values of the Active Mortgages that have one (chapter 012, lesson 5). The Projection divides each future month's Outstanding by today's Collateral Value (chapter 004, lesson 5).

The hand value ignores the Gold Rate completely, so it doesn't follow the price. Clearing goes back to whatever the Gold Rate is now, not what it was when the value was set.

(b) Rounding half-up to the paisa

Whole grams at whole rupees never have a fraction. Odd weights and rates do. Calling collateral_of directly:

(c) No Gold Rate yet

On a fresh database every rate is null, so every Mortgage's collateral is null, its Loan-to-Value too, and it's never on the Call List for Loan-to-Value. If only some purities have a rate, the Dashboard total skips the Mortgages of the others: they count neither in the value nor in what's owed against it (dashboard.py, line 225).

(d) A rate's date moves only when the rate changes

Predict: on 1 Oct the Lender sets all five rates. On 19 Oct the Settings page sends all five again, with only 22K changed. What is each updated_on?

22K says 19 Oct; the other four still say 1 Oct. That's the comparison at line 106. On the sample book all five say 19 Oct, because book.py changed all five that day. The Mortgage page's CollateralPanel shows set_on ("at the 22K Gold Rate of …"), so the Lender can see when a rate is stale. (From scripts/run_throughs.py, section L5, on a fresh database.)

Quiz

Sunita's mangalsutra is 10 g net at 22K and owes ₹35,677. What is its Loan-to-Value on 19 Oct?

Collateral Value = 10 g × ₹13,536 = ₹1,35,360. Loan-to-Value is Outstanding ÷ Collateral Value = 0.2636. The first option used paise for one side and rupees for the other (trap #6); the third divided the wrong way round.

The Lender raises the 22K Gold Rate. Which Mortgage's Collateral Value does not change?

A value set by hand wins over the Gold Rate (line 65). A closed Mortgage is still valued at the Gold Rate on its page. Nothing remembers an older rate: the current one is always used.

Where is Arjun's ring's ₹81,216 stored?

config holds the rate per gram (1353600), not any Mortgage's value. collateral_override is NULL unless the Lender sets a value by hand. The ₹81,216 is computed each time from the weight and the rate.
