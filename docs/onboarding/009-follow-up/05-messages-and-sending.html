Chapter 009 · Lesson 5

Messages: templates, cards and click-to-send

Sunita's Reminder is thirteen lines of text with a small table in the middle. This lesson reads it line by line, shows which parts the Lender can rewrite and which they can't, and follows the text out of the app into WhatsApp.

By the end you can change a template safely, and explain how a message reaches WhatsApp.

The problem

Receipts and Reminders go to Customers on WhatsApp, usually read on a phone. That brings three problems.

  • WhatsApp has no tables. A Customer with two Mortgages needs to see two sets of figures that line up. In an ordinary font, "₹700" and "₹35,723" won't line up however many spaces you add.
  • The Lender wants their own words. "Namaste" or "Dear", Hindi or English, with or without emoji. So the text around the figures is a template the Lender edits. But a template with a typo, like {name} for {customer_name}, would reach the Customer as "Namaste {name}". That's embarrassing, and it can't be unsent.
  • The app can't send WhatsApp messages itself without breaking WhatsApp's rules (ADR 0002).

The idea

The figures are built by the app as cards: one small block per Mortgage, inside WhatsApp's monospace formatting (text between ``` fences is shown in a fixed-width font), with amounts right-aligned. The Lender's template says where the cards go, with a {mortgages} placeholder.

Each template has a fixed list of placeholders it may use. Saving a template with any other brace in it is refused, so a typo is caught when the Lender saves, not when the Customer reads it.

Sending is click-to-send: the app opens WhatsApp with the message already typed, and the Lender presses Send. All of that sits behind one small frontend object, sender, so it can be replaced by real automation later without touching any page.

The flow

Reminder that the frontend never builds a message. Receipts take the same path: receipt_text sits next to reminder_text, and the Receipt route returns its text (chapter 007).

The code

1. Cards

  1. Every line in the block is the same width: at least 24 characters, more if some label and amount need it (with one space between). *( … ) spreads the generator's values into max as separate arguments.
  2. rjust pads the amount with spaces on the left, so every amount ends in the same column.
  3. The title is the Mortgage's description, wrapped to the width. textwrap.wrap breaks at spaces, so "Gold chain with Lakshmi pendant" (31 characters) becomes "Gold chain with Lakshmi" and "pendant".
  4. Totals only appear with two or more cards. With one card they'd just repeat it.

2. A Reminder's text

Cards are titled by the jewellery's description, as the Customer knows it ("Mangalsutra"), never by the Mortgage Name ("2026-Sunita-Mangalsutra"), which is the Lender's internal label (trap #16, owned by chapter 007). receipt_text (line 132) is built the same way, with four rows per card (Paid, Interest, Principal, Still owed) and a "(Redeemed)" suffix on the title when that Payment Redeemed the Mortgage.

3. Placeholders: allowed, checked, filled

  1. The regex reads: a {, then any characters that aren't braces, then a } if there is one. So it catches {name}, { amount } and a brace left open, {date.
  2. dict.fromkeys removes repeats but keeps the order they were first seen in (a set wouldn't keep the order).
  3. fill is forgiving: an unknown placeholder stays as written. It doesn't need to be strict, because a template can't be saved with one. The strictness lives in one place, the save.

A Reminder has no {amount} or {method}, because nothing was paid. A Receipt has no {interest}. Each list matches what its …_text function fills in.

4. Refusing a template at save

The refusal names each bad brace and lists the usable ones, so the Lender can fix it. GET /api/settings/messages/placeholders (line 113) publishes both lists, and the Settings page shows them. The defaults are RECEIPT_TEMPLATE and REMINDER_TEMPLATE (lines 20–41); MessageSettings (line 44) uses them until the Lender saves their own, and refuses an empty template (min_length=1).

5. Out to WhatsApp

  1. Pages import sender, never clickToSend. To move to the WhatsApp Business API, write a second MessageSender and change this one line (ADR 0002).
  2. Phone numbers are stored as 10 digits (chapter 008). WhatsApp wants the full international number, so 91 is added here and nowhere else. URLSearchParams URL-encodes the text: newlines, ₹ and emoji included.
  3. wa.me is WhatsApp's short link, but it redirects to this one and the redirect turns emoji into "�" (the comment at lines 24–27). So the app uses the long link directly.

Only two places call sender: SendOnWhatsApp in components/WhatsApp.tsx (Receipts and Reminders) uses send; CallListPage uses chat, to open a conversation with no text. Both are chapter 012, lesson 5's.

put() { curl -s -X PUT -H 'content-type: application/json' --data-binary @- http://127.0.0.1:8765/api/settings/messages; }

One Reminder, two cards, ordered by Mortgage Name (_accruing sorts by name), with a 24-character rule and the totals. The line above the block says "interest of *₹3,400*". The bangles' Term Change to 1.5% from 25 Oct (chapter 006) doesn't lower this month: the month ending on 25 Oct is charged at 2%.

(b) A card that has to widen

Calling reminder_text directly with a made-up ₹12,34,567 of interest: "Interest added" (14) + a space + "₹12,34,567" (10) is 25 characters, so every line of the block becomes 25 wide, and the amounts still line up. (d) The link WhatsApp opens

Running the real messaging.ts under Node, with window.open replaced by a function that records its arguments, sender.send("9860067890", message) opens:

https://api.whatsapp.com/send/?phone=919860067890&text=*Interest+reminder*+%F0%9F%94%94%0A%0ANamaste+Sunita+Rao%2C%0A…

From scripts/run_throughs.py (section L5), which runs frontend/src/messaging.ts with Node 26's built-in TypeScript support. Target _blank, features noopener. sender.chat opens the same link with no text.

%F0%9F%94%94 is 🔔 in UTF-8, and %0A a newline. Everything the backend built arrives in WhatsApp's text box, character for character. Don't press Send on the sample book: its numbers are invented but realistic.

Quiz

The Lender saves the Reminder template Dear {customer_name}, pay {amount} by {date}. What happens?

amount is a Receipt placeholder, not a Reminder one. template_refusal finds {amount} among the braces and refuses the save. Only fill would leave it as typed, and it never sees a refused template.

Why does a Reminder with one card show no "Total owed" line in the block?

Line 93: if len(cards) > 1. With one card the totals would repeat it. {total_owed} is a separate placeholder outside the block, used by the default template either way.

The owner wants messages sent by the WhatsApp Business API. What's the smallest frontend change?

Pages only call sender.send and sender.chat. Swap the object behind sender and they all follow (ADR 0002). wa.me would break emoji and still be click-to-send. (Sending from the backend would need more work there too.)
