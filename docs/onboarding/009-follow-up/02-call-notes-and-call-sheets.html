Chapter 009 · Lesson 2

Call Notes and Call Sheets

The Lender rang Arjun and he said "Will pay after Diwali". That sentence is now a row in the database. This lesson shows the two ways such a row gets there, and the one set of rules both ways share.

By the end you can record a call one at a time or from a Call Sheet, and say why an imported row was left out.

The problem

A call is only useful if someone remembers what was said. Next week, when Arjun still hasn't paid, the Lender wants to see "19 Oct: Will pay after Diwali" next to his ring.

Sometimes the Lender makes the calls from the app, one at a time. Sometimes someone else does: a family member with a printout and a pen, or a spreadsheet on another laptop. Their notes have to come back into the app without anyone retyping them, and without mistakes. A note for a Mortgage that was closed this morning, or a date typed as "next Tuesday", has to be caught. If the same sheet is imported twice by accident, no note should appear twice.

The idea

A Call Note is one row: a Mortgage, the day it was called on, and what was said. It is added either on its own, from the Mortgage page, or in bulk from a Call Sheet: the day's Call List exported to Excel or PDF, filled in, and (for Excel) imported back.

Both ways call one function to decide whether a note can be added. So the rules can't drift apart. Both also keep an exact duplicate (same Mortgage, same date, same text) only once, which makes importing the same sheet twice harmless.

The flow

Reminder the PDF has no way back in. It's for someone with a pen. Only the Excel sheet is imported.

The code

1. The one set of rules

  1. Only Active Mortgages take Call Notes. A Dormant one is Active (Dormant isn't a stored status, chapter 005), so it can still be noted: you may well phone a Customer to ask about jewellery that should have gone back.
  2. The function returns the reason as a sentence for the Lender, or None. It doesn't raise. Each caller decides what a reason means: a 422 for one note, a "left out" line for an import.

2. One at a time

  1. A note added on its own is always dated today. There's no date field in CallNoteIn, only note.
  2. The same note twice on the same day gives back the first row, with a 201 both times. A double-click can't make two notes.

The route is POST /api/mortgages/{mortgage_id}/call-notes (line 95), body {"note": "…"}. GET on the same path (line 104) lists a Mortgage's notes, newest first.

3. The sheet's columns

  1. Excel groups digits in threes (1,512,000). Indian grouping is 15,12,000. Excel has no setting for that, so this number format picks a pattern by size: [>=100000] means "for 1,00,000 or more, use the next pattern". The cell holds a plain number, so the sheet can still add it up.
  2. Each Column gives two values: one for Excel (a number) and one printed (text). lambda r, _: … is a small unnamed function taking the row and the export date. The _ is a parameter it ignores.
  3. Called on is pre-filled with the export date. Whoever makes the calls changes it only if they call on another day.

sheet_rows (line 149) builds the rows from call_list(), so the sheet is exactly lesson 1's list, in its order, adding each Mortgage's description and latest Call Note. excel_sheet (line 184) freezes the heading row. pdf_sheet (line 206) prints a landscape A4 table in DejaVu Sans, from follow_up/fonts, because PDF's built-in fonts have no ₹ sign.

4. Reading a sheet back

  1. The headings are found by name, not by position. Someone can add a title row on top, or move columns around, and the import still works.
  2. <= between two sets means "is a subset of". Only three columns are read back: Mortgage Name, Called on and Call Note. Everything else on the sheet is ignored.

5. What an import would add

  1. A row with no note is the normal case (not every call gets a note), so it's counted, not reported. Lines with neither name nor note aren't even counted.
  2. casefold() is a stronger lower(). Mortgage Names are unique ignoring case, so this lookup can't be ambiguous.
  3. A note already stored, or already earlier on this sheet, for that Mortgage and date is counted as a duplicate. That's what makes importing twice add nothing.

_left_out_because (line 316) checks the sheet's own problems first ("no Mortgage Name", "no such Mortgage", "Called on is not a date"), then calls call_notes.left_out_because from snippet 1. _as_date (line 260) accepts a real Excel date or text such as 2026-10-19, 19 Oct 2026 or 19/10/2026.

Both routes call read_import. POST /api/call-list/import-preview (line 421) runs it on engine.connect() and returns the answer. POST /api/call-list/import (line 431) runs it inside engine.begin() and inserts every row in adding. Unlike chapter 006's Previews, nothing is written and rolled back: the Preview simply stops before the insert. The same function gives the same answer either way.

(c) Call Notes are not History

After all of those, the audit_entry table (History, chapter 006) still has 271 rows, as on a fresh book. A Call Note doesn't change a Customer, a Mortgage or a Payment. It's a record in its own right, and nothing edits or deletes one: there's no route for either.

call_note.created_at is filled in by the database's own clock (server_default=func.now()), not the app's business date. On the sample book it's the moment you built it, not 19 Oct. The date that matters is called_on.

Quiz

A Call Sheet exported on 19 Oct is filled in and imported on 21 Oct, with Called on left as it was. What date do its notes get?

An import uses the sheet's Called on, which the export pre-filled with 19 Oct. 19 Oct isn't after 21 Oct, so the notes are added. Only a note added on its own is dated today.

Kavita's anklet is Dormant. Can the Lender add a Call Note to it?

left_out_because checks status, and a Dormant Mortgage's status is active. It's the Call List that skips Dormant Mortgages, not Call Notes. (test_call_notes.py::test_a_dormant_mortgage_takes_call_notes_both_ways.)

Why does importing the same sheet twice add nothing the second time?

read_import loads every stored (called_on, note) per Mortgage first and counts a match as skipped_duplicates. Nothing records the file itself, and the answer is a 200 either way.
