Chapter 015 · Lesson 5

Bringing a Backup back

The app has restored a database before. Now make the whole book usable again: the database and every photo must travel together.

By the end you can restore a Backup by hand on a stopped app, and explain how the same steps move a book to a new laptop.

The problem

A Backup is an archive, not a live database. Replacing only mortgage.db can leave records pointing to missing photos; extracting over a database the app is currently using can also corrupt the result. Restoring replaces all changes made since that archive was taken.

The idea

Stop the app, open the selected zip (enter its password if it has one), replace both mortgage.db and photos/ in the data folder, then start the app. For a migration rollback, select the named -before-update Backup and start the previous version too. For a new laptop, install the app there and restore the latest Backup in the new data folder.

The flow

The code and the instructions

Restore is intentionally a user operation described in the install guide, rather than an API call that silently replaces data. Setup finds a likely -before-update zip and names it in the failure message; the Lender decides whether to restore.

This locates a recent candidate in the configured Backup folder. It does not open or restore the archive. The manual steps in docs/install.html tell the Lender exactly what to replace.

Run-through: restore the sample book on your copy

Use the $COPY exported in the backend terminal in lesson 1. Stop that server with Ctrl-C. Choose the newest -before-update zip produced in lesson 4 (or the lesson 1 zip when you are practising restore on its own). It has no password because the sample server has no Backup password configured.

mkdir "$COPY/restore"
BACKUP=$(ls -t "$COPY"/backups/*-before-update*.zip | head -n 1)
unzip "$BACKUP" -d "$COPY/restore"
cp "$COPY/restore/mortgage.db" "$COPY/data/mortgage.db"
rm -rf "$COPY/data/photos"
cp -R "$COPY/restore/photos" "$COPY/data/photos"
uv run python ../docs/sample-book/serve.py "$COPY" 8766

Open the served book and compare Meera's chain with The Gold Chain Story. The Backup was made on 19 Oct 2026, so the sample book's figures return. The same restore replaces the data folder contents on a new laptop after installing the app there. On Docker, choose the old release in APP_VERSION (or use Setup to switch to the previous version) before starting a restored pre-migration database.

Restoring replaces later work. Any Payments or other changes made after the Backup was taken disappear when its database and photos replace the current ones. Stop the app first and preserve the two archive contents together.

Nuance

Predict: A Backup is password-protected. Can Finder or Explorer extract it without the password?

No. Without the password, the archive cannot be opened. Store the password safely apart from the laptop and Backup folder.

Predict: The Lender uninstalls the app before moving to a new laptop. Where does Uninstall keep the latest Backup?

In Documents, before removing app files. Copy that zip somewhere safe and restore it on the new installation. Moving the Backup destination means changing BACKUP_DIR in .env and restarting the app.

Quiz

What must be replaced from the Backup to restore the whole book?

The database refers to the photo files; the archive contains both, and they must be restored as one set.
