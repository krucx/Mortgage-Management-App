Chapter 002 · Check yourself

Check yourself

Questions mixed from all five lessons, then your first change in the real repo: follow one glossary term all the way into the code and its test, break it on purpose, and watch the tests catch it.

Quiz: where would you look?

1. A Receipt's wording is wrong. Which backend package holds Receipts?

payments/receipts.py. The payments/ package is "Payments, their Allocations and Receipts". follow_up/ holds Notices and the Call List; safekeeping/ holds History and Backups.

2. You want to know why a Customer is identified by their phone number. Where do you look?

"Why" questions about design go to the ADRs: 0005, "A person is identified by their Primary Number". A migration shows what the schema is, and a docstring may describe the rule, but the ADR records the reasons.

3. Your issue title reads "Fix due date shown for a loan". How should it read?

"Due date" and "loan" are Avoid words; the glossary's terms are Accrual Date and Mortgage. "Pledge" and "item" are on Mortgage's Avoid list too.

4. A trace: on the served sample book, GET /api/mortgages/2 has a last Ledger step with "amount": 53300. What is it?

Amounts are in paise, so 53300 is ₹533, and the chain's last step is its interest_to_date step: 10 days of the month that began on 10 Oct, at ₹1,600 a month. The held clock keeps it at ₹533 every time you serve the book.

5. A page is at /payments/:id/receipt. How do you find its file?

App.tsx maps every screen address to its page: here ReceiptPage in pages/. main.py is the backend's map, and components/ holds shared parts, not pages.

6. A trace: cd backend, then BACKUP_DIR=/tmp/b uv run uvicorn mortgage_backend.main:app. Which database file opens?

DATA_DIR wasn't set, so data_dir() returns the relative data, from backend/. BACKUP_DIR only says where Backups go. The root's data/ would open only if you started uvicorn from the root.

7. You edited NewPaymentPage.tsx but 127.0.0.1:8765 still shows the old page. Why?

serve.py serves the built frontend/dist. Rebuild, or use npm run dev on :5173 for live edits.

8. Where is the code that records a new Payment, POST /api/payments?

Every change that moves a Ledger, Payments included, lives in lending/changes.py. payments/payments.py only reads Payments. Search for the route's path, not the folder name.

Hands-on: follow Default Terms into the code, then break it

This is your first change in the real repo. It is safe: the tests use throwaway databases, and you'll undo the change at the end.

1. Follow the term

The client argument is a pytest fixture: a value pytest builds and passes in by name. It's defined in tests/conftest.py (lines 14–22): a fresh database file in a temporary folder, and the real app on it. Starting the app runs every migration, 0001 first, so each test sees a brand-new database.

2. Run the test

cd backend
uv run pytest tests/test_default_terms.py

Expect 8 passed: the two plain tests, plus the six cases of the parametrized one (@pytest.mark.parametrize runs one test function once per listed input).

3. Break it, and predict

In 0001_config_table.py, line 25, change "300" to "200". Save.

Predict: of the 8 tests, which fail? Think about every assertion that compares with DEFAULTS.

Run it again. At commit 55ee8cb, 7 fail and 1 passes:

If you predicted only the first test, you're in good company: that's the one whose name mentions 3%. The lesson is that a test's helper constants (DEFAULTS) are assertions too. And none of this touched a real database: each test migrated its own from scratch.

4. Undo it

git checkout -- src/mortgage_backend/migrations/versions/0001_config_table.py
uv run pytest tests/test_default_terms.py   # 8 passed again
git status                                  # clean

(From backend/. From the repo root, the path is backend/src/mortgage_backend/migrations/versions/0001_config_table.py.)

Never edit a released migration for real. Every Lender's database has already run migration 0001; editing it changes nothing for them and makes new databases differ from old ones. To change the Default Terms of new databases, you'd add a new revision. Chapter 010, lesson 6 explains migrations and why.

Recap

  • The repo is a backend and a frontend, plus the things that ship them (windows/, the compose files), show them (docs/) and explain them (Documentation/, Documentation/GLOSSARY.md). Lesson 1
  • App.tsx maps addresses to pages; main.py includes every router; the request's URL string connects them. Payment writes live in lending/changes.py. Lesson 2
  • Documentation/GLOSSARY.md says what a word means and what not to call it; the ADRs say why a rule is the way it is. Lesson 3
  • book.py builds the sample book through the API into a fresh folder; serve.py serves it with the clock held on 19 Oct 2026. A fresh database's Default Terms are 3% full month; the book's are 2% pro-rata. Lesson 4
  • For hot reload, Vite on :5173 proxies /api to :8000: the sample book or uvicorn. Always pass scratch DATA_DIR and BACKUP_DIR, and on every docker compose command. Lesson 5
