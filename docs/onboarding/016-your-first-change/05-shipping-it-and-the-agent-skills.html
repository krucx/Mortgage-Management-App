Chapter 016 · Lesson 5

Shipping it, and the agent skills

A change is complete when its checks pass and its commit explains the behavior. A release later adds coordinated version and CHANGELOG work.

By the end: you can name the checks, write a repo-shaped commit and describe the agent workflow.

The problem

A correct local implementation can still be hard to review if its commit message is vague or the issue's behavior is missing from release notes.

The idea

Run all CI checks and local lint, write the commit message using glossary terms and the issue number, and draft the CHANGELOG note for a future release. This change does not alter the database. Link back to 015 · Lesson 2 rather than cutting a release here.

Run-through

On the practice branch, run uv run pytest, npm test, npm run typecheck, backend mypy and frontend lint. CI runs frontend lint. Hosted CodeQL and Trivy scans run separately on GitHub. Draft a commit such as Edit a coming Term Change (#213) and a CHANGELOG bullet saying the change adds a Preview and History, with no database change. Then delete the practice branch after returning to main.

Read .claude/skills/wayfinder through map #92, then grill-with-docs, domain-modeling, to-spec, to-tickets, implement, tdd and teach. Map and ticket creation is covered by issue-tracker.md. Research branches can be pushed and left unmerged; the practice branch stays local. The chapter publishing workflow itself commits to main.

Which check runs in the frontend CI job?

The frontend job runs typecheck, lint and tests. Hosted scans run in separate workflows.

Try the tests first; then compare your implementation with the behavior list and nearby examples above.
