Chapter 016 · Lesson 5

Shipping it, and the agent skills

A change is complete when its checks pass, its pull request explains the behavior, its automated review is answered, and a human has approved it. A release later adds coordinated version and CHANGELOG work.

By the end: you can name the checks, write a repo-shaped commit and pull request, and describe the agent workflow.

The problem

A correct local implementation can still be hard to review if its commit message is vague or the issue's behavior is missing from release notes.

The idea

Run all CI checks and local lint, write the commit message using glossary terms and the issue number, and draft the CHANGELOG note under ## Unreleased for a future release (never edit VERSION: the release candidate workflow does). Then open a pull request targeting main: say what the Lender sees change, how you verified it, and any risk. Answer every CodeRabbit finding, fixing it or replying why it doesn't apply, and wait for a human approval and the required checks. You never merge your own change. This change does not alter the database. Link back to 015 · Lesson 2 rather than cutting a release here.

Run-through

On the practice branch, run uv run pytest, npm test, npm run typecheck, backend mypy and frontend lint. CI runs frontend lint. Hosted CodeQL and Trivy scans run separately on GitHub. Draft a commit such as Edit a coming Term Change (#213) and a CHANGELOG bullet saying the change adds a Preview and History, with no database change. Then delete the practice branch after returning to main.

Read .claude/skills/wayfinder through map #92, then grill-with-docs, domain-modeling, to-spec, to-tickets, implement, tdd and teach. Map and ticket creation is covered by issue-tracker.md. Research branches can be pushed and left unmerged; the practice branch stays local. The implement skill ends by opening a pull request rather than stopping at a commit, and chapters published by teach go through a pull request too.

Your pull request has a CodeRabbit approval and green checks. Can it merge?

CodeRabbit is advisory and never counts as approval (ADR 0019). The bypass is for a maintainer overriding the gates on purpose, with a recorded reason.

Which check runs in the frontend CI job?

The frontend job runs typecheck, lint and tests. Hosted scans run in separate workflows.

Try the tests first; then compare your implementation with the behavior list and nearby examples above.
