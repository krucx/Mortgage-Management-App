Mixed questions

Why does the practice branch stay local?

It is a contained exercise; normal work and chapter publishing go straight to main.

When is an issue ready for an agent?

Otherwise it may need information or human product judgment.

Why does Edit a Term Change need no ADR?

It fails the repo's three-part ADR test.

Why can only coming Term Changes be edited?

Changing it would rewrite history; add a later Term Change instead.

What does the edit Preview run?

The shared function makes Preview and save refuse the same invalid edit.

Why regenerate API types?

Generated types should never be hand-edited.

Which skill turns a conversation into tickets, and which charts a map?

Wayfinder plans a map; to-tickets makes issues from the specification.

Hands-on: test the boundary

On main, run the baseline:

cd backend
uv run pytest tests/test_term_changes.py

At the checked main baseline, 11 pass. In remove_term_change, change effective_on <= today to effective_on < today and run the file again. Exactly test_a_term_change_can_be_removed_until_it_takes_effect fails: a Term Change effective today must not be removable. Undo with:

git checkout -- src/mortgage_backend/lending/changes.py

On practice/edit-a-term-change, make the same boundary mistake in your edit_term_change. At least one of your tests must fail. If none does, write the today-boundary test, observe it fail on the broken line, then undo the mutation. Finally run every check (uv run pytest, npm test, npm run typecheck, uv run mypy src, npm run lint) and delete the practice branch.
