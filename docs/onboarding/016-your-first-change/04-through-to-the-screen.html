Chapter 016 · Lesson 4

Through to the screen

The backend contract is ready. Now connect generated types, typed requests and an interaction that shows a Preview before saving.

By the end: you can wire an edit control and test its requests with the frontend's fake server.

The problem

Writing API paths by hand can silently drift from backend models. The Terms panel already shows coming changes and Remove, giving us a pattern for a second action.

The idea

Run npm run gen:types, then add named request functions in requests.ts. In the panel, gather the new date and rate, show ChangePreview, and save through useMortgageChange. Keep the UI's date aligned with the browser's today (012 · Lesson 1).

Run-through: Meera's bangles

Start a fresh sample book in a scratch folder, build the frontend, and serve it using the command sheet. In the Terms panel change 25 Oct to 25 Nov and the rate to 1%. Read the Preview before confirming; after saving, verify the Terms and History. Never start unreleased code on a real book (trap #9).

Add TermsPanel.test.tsx with fakeServer/showPage. Assert the edit Preview request, confirm action, save request and rendered updated date. This is the first test pinning the panel's remove/edit controls; see issue #120 if its existing coverage has since changed.

Generate openapi.json and api.gen.ts; never hand-edit generated API types (trap #10). The frontend data hook and cache behavior are in 011 · Lesson 4.

Why regenerate API types after adding the backend routes?

Generation keeps the frontend request contract in step with the API.
