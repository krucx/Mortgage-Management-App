Chapter 002 · Lesson 2

Inside the backend and the frontend

The Lender opens Meera's gold chain and sees its Ledger and Outstanding. Which file drew that screen, which request did it send, and which Python function answered?

By the end you can find the file behind a screen or a route.

The problem

The backend has nearly 40 Python modules and the frontend nearly 90 TypeScript files. A bug report never names a file. It says "the chain's page shows the wrong Outstanding". You need a route from what the Lender sees to the code that produced it, and you need it to work for any screen, not just one you've memorised.

The idea

Each half has one file that lists everything. In the frontend it is App.tsx: every screen's address and the page component that draws it. In the backend it is main.py: every group of API routes the app has. Between them, the request's URL is the thread you follow.

The flow

The names on each box are real: search for them and you land on the line. Lessons later in the course open each box. Today you only learn to walk the path.

The backend: main.py is the map

create_app builds the whole FastAPI app. It is the backend's composition root: the one place where every part is created and plugged together. Chapter 010 explains it properly; for finding your way, only its end matters.

  1. today is passed in as a function. Tests and the sample book pass a different one to hold the clock still. You'll use that in lesson 4.
  2. Each include_router adds one module's routes. A FastAPI router is a group of routes declared with decorators like @router.get("/mortgages/{mortgage_id}"). The module's name tells you the package it came from, via the imports at the top of the file.

The imports at the top of main.py group the routers by package. Those packages are the backend's seven sections:

Two more files sit beside main.py: openapi.py writes the API's schema to frontend/openapi.json, from which the frontend's types are generated, and migrations/ holds the database's Alembic revisions (chapter 010).

The frontend: App.tsx is the map

The frontend is a single-page app: the browser loads it once and React Router swaps pages as the address changes. App.tsx lists every address.

:id is a placeholder: /mortgages/2 draws MortgagePage with id = 2. The rest of frontend/src/ is laid out like this:

Path in frontend/src/What's there
pages/One file per screen, named …Page.tsx, each listed in App.tsx
components/Parts pages share: panels, dialogs, and hooks (functions named use…, React's way of sharing stateful logic between components)
requests.tsEvery request the screens make, as a named function
serverState.tsThe typed API client, the cache and its keys (chapter 011)
api.gen.ts, api.tsRequest and response types, generated from the backend (npm run gen:types); api.ts gives them short names. Never edit api.gen.ts by hand.
money.ts, format.ts, terms.ts, …Small helpers: rupees in Indian grouping, dates, describing Terms

Run-through: Meera's chain, from screen to function

On the sample book (lesson 4 shows you how to serve it) Meera's gold chain, 2025-Meera-GoldChainPendant, has id 2, so its screen is at /mortgages/2. Follow it.

Hop 1: the page asks for the Mortgage.

useQuery comes from TanStack Query, a library that fetches data, caches it and re-renders the page when it arrives. The page doesn't build the request itself; it names one from requests.ts.

Hop 2: the request.

The URL template '/api/mortgages/{mortgage_id}' is the thread. It is written exactly as the backend declares it, and TypeScript checks it against the generated types, so a typo won't compile. Copy it and search the backend.

Hop 3: the backend route. Searching for "/mortgages/{mortgage_id}" finds it in lending/mortgages.py, the module main.py included as mortgages.router.

EngineDep and TodayDep are FastAPI dependencies: FastAPI fills them in on each request with the app's database engine and its idea of today. load_mortgage replays the chain's Ledger and works out its Outstanding (chapters 004 and 005).

Things the folder names won't tell you

Two places where the obvious guess is wrong. Each gets its full explanation in a later chapter; for now, just don't be surprised.

Predict: you're asked to change what happens when a Payment is recorded (POST /api/payments). Which file holds that route?

Not payments/payments.py. That file only reads Payments (GET /api/payments, GET /api/payments/{payment_id}, the payment methods). The write is in lending/changes.py, at @router.post("/payments", …), beside every other change that moves a Ledger: creating and editing Mortgages, Voiding Payments, Term Changes, Closures and Reopening. Keeping them in one module means every change is refused, written and checked the same way. Chapters 003 and 006 walk through it.

Search the route, not the folder. When you need the code behind a URL, grep for the path string ("/payments") across backend/src/ rather than guessing from package names.

Predict: the backend tests make test data over HTTP with helpers in backend/tests/api_seed.py. Why not the shorter, more obvious name http.py?

Because backend/tests/ is on Python's import path when pytest runs, so the tests can import seed directly. A file called http.py there would hide Python's own http module from everything that imports it, including the web libraries. The file's docstring says so. Chapter 013 covers the test helpers.

Quiz

The Closures screen shows a wrong count. Where do you look first to find its page?

App.tsx maps /closures to ClosuresPage; from there you follow its requests. components/ holds shared parts, not pages, and main.py is the backend's end of the thread, not the start.

Which backend package would hold the code that decides whether to phone a Customer today?

The Call List lives in follow_up/call_list.py. people/ is about identifying Customers and Referrers, and lending/ computes the figures the Call List reads, but not the list itself.

You change a field the backend returns. Which frontend file must you never edit by hand?

api.gen.ts is written by npm run gen:types from the backend's schema. requests.ts and App.tsx are written by people.

Go deeper

Read all of main.py (about 145 lines) and the seven packages' __init__.py docstrings. Then pick any screen in App.tsx and walk its four hops on your own.
