Reference sheet

The frontend's data layer

How the screens ask the backend for anything: the hooks a page uses, the cache's keys, what each kind of change makes stale, and every read, list, Preview and change in frontend/src/requests.ts with the route it calls. Taught in chapter 011. Chapter 012 added each page and the routes it calls (below).

The rules in one breath. Every request goes through the typed client, by a function in requests.ts; never fetch (trap #11). Change a backend model, run npm run gen:types and commit openapi.json and api.gen.ts (trap #10). Every key comes from keys in serverState.ts. A page saves through useLedgerChange, useMortgageChange or useChange(STALE_AFTER.…); what goes stale is declared there, not in the page.

The cache's keys

From keys in serverState.ts. A key is a path: making a prefix stale reaches every key under it.

['backups']the Backups' state; asked every second while one runs

What goes stale

"Asked now" means asked again at once if on screen; everything listed is marked stale either way, and the rest is asked when next shown.

ChangeSave throughAsked now, if on screenMarked only
