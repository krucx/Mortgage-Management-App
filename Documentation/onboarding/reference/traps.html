Traps: what surprises newcomers

The things in this codebase a new developer is most likely to trip on. Each has one chapter that owns it (explains it fully) and may be warned about earlier. Numbers are fixed, so lessons can say "trap #1". This sheet lists the traps the course has met so far, and grows as chapters are written.

#The trapWarned inOwned by
1Payment write routes live in lending/changes.py, not in payments/. payments/ holds reads, Receipts and the Cash Limit. Every Ledger-changing write, for Mortgages and Payments alike, is in that one module.002 · 2, 006 · 1, 007 · 1003 · 3
2One Payment can be several payment rows. A Final Payment is kept as a part of its own, pointing back through received_with, which the API never shows; the id POST /api/payments returns is the first part.003 · 5, 005 · 3, 007 · 4, 007 · 5007 · 2
3Paying exactly the Outstanding Redeems the Mortgage, in the same request (ADR 0011): record_payment's _redeemed_by compares each Allocation with the quote on its date. A whole Outstanding that can't Redeem is refused, with the rest of the Payment; a rupee less is an ordinary Payment.003 · 2, 003 · 4, 004 · 3, 006 · 2, 007 · 2, 012 · 3005 · 3
4Nothing owed is stored. No ledger table, no stored Outstanding, no stored interest-paid. Changing an old Payment changes every later figure, on purpose (ADR 0001).001 · 5, 003 · 4, 005 · 1, 006 · 2, 007 · 1, 008 · 5004 · 1
5Previews run the real change and roll it back, so a bug in a change shows up in its Preview too, and a Preview is refused exactly when saving would be. Debug the change function in changes.py, not previews.py. The Preview routes are hand-written on purpose (ADR 0007).003 · 2, 004 · 1, 005 · 3, 008 · 3, 011 · 4, 012 · 2006 · 4
6Units: paise (integers), milligrams, basis points per month, and "out of 30 days" for pro-rata. ₹1,00,000 is Indian digit grouping.002 · 4, 003 · 2, 007 · 1, 008 · 5, 010 · 4, 011 · 1, 011 · 4, 012 · 1, 013 · 2, 013 · 4004 · 2
7A month starts before the day's Payments. A month is charged on the Principal at its start; a Payment on an Accrual Date comes after that day's interest and belongs to the new month; today always counts in the Interest to Date. Paying Principal never lowers the month it's paid in (ADR 0006).007 · 5004 · 3
8No scheduler. The daily jobs (Backups, Notices) run on the first /api/ request of the day, from middleware. And Notices don't wait for it: notices.sync also runs on every read of the Notices or the Dashboard, and whenever the message settings are saved, so GET /api/notices and GET /api/dashboard write. sync is safe to repeat; missed days are made up only for Accrual Dates still to come.002 · 5, 003 · 3, 004 · 5, 012 · 5010 · 2 (the mechanism); 009 · 3 (the Notice half)
9Migrations run on every start, after a Backup, with no way back. Unreleased code started on real data migrates it for good, and the released app then refuses to open it ("from a newer version of the app"); the only way back is restoring the -before-update Backup. Use a scratch DATA_DIR and BACKUP_DIR on every command, and never restart the served book while a new migration exists.002 · 5, 010 · 6, 014 · 1, 014 · 4010 · 5
10API types are generated. Change a backend model, run npm run gen:types, commit openapi.json and api.gen.ts, or tests fail in both languages.002 · 2, 003 · 2, 006 · 5, 010, 013 · 1, 013 · 4011 · 1
11The frontend never calls fetch. Every request goes through the typed client in serverState.ts, by a function in requests.ts, so it is type-checked, cached and made stale by saves. oxlint bans fetch outside createServerState, but CI doesn't run lint; in tests, showPage fails a page that calls it.013 · 1, 013 · 4011 · 1
12Plain docker compose up runs the published image, not your code. docker-compose.yml names krucx11/mortgage-management-app:latest (the one you last pulled); docker-compose.dev.yml builds yours as mortgage-management-app:dev, never replacing it, and a later plain up -d goes back to the published one. Pass scratch DATA_DIR/BACKUP_DIR on every compose command: with a .env beside the Compose file, a command without them silently uses .env's folders (without one, it refuses: "required variable DATA_DIR is missing a value").002 · 5, 013 · 1014 · 1
13Two caches decide when the installed app updates. The service worker's (vite.config.ts: the precache, pages NetworkFirst) and the browser's HTTP cache, which follows the Cache-Control headers platform/screens.py sends (pages, sw.js and the manifest no-cache; /assets/ immutable). They must agree, or an update reaches the Lender late. Since ADR 0013 the backend serves the screens in Docker too, so screens.py is the only place for the headers; before it, nginx's had to match by hand (the gap filed as #117, closed with nginx). test_screens.py pins pages, sw.js and the manifest no-cache and /assets/ immutable; not registerSW.js.012 · 6014 · 2
14The Windows scripts have rules of their own. They run on Windows PowerShell 5.1, which reads a script without a byte-order mark in the PC's old code page, so every file in windows/ is ASCII only (Pester in Docker runs PowerShell 7 and won't catch a stray character; CI's Windows runner will). app is a junction to versions\<version>, moved only once a new version answers. docs/Setup.bat must stay byte-identical to windows/Setup.bat (CI's pages job runs cmp). Pester runs on a Mac only in the Debian arm64 image from chapter 013.013 · 1, 014 · 4014 · 3
16Customer-facing text hides internal names. Receipts and Notices use the jewellery's description and the Customer's name, never the Mortgage Name or ids.003 · 5, 005 · 4, 009 · 5, 012 · 1007 · 5
17The tests' today is 20 Apr 2026, fixed in conftest.py (TODAY), not the sample book's 19 Oct 2026 and not the computer's date: move it a day and 48 tests fail. Below the API there is no single today: seed.py makes each change on its own date, as the Lender would have that day, so a seed is refused exactly when the app would have refused it then. In a client test, a Payment dated after 20 Apr is "in the future".013 · 2013 · 3
18backend/tests/ is on the import path, hence api_seed.py rather than http.py, which would hide Python's http: FastAPI would load the test file instead, and every test fails at conftest with a circular-import error in FastAPI. Never name a file there after a standard-library module.002 · 2013 · 2
19The glossary's Avoid words are kept by convention only. No linter or test enforces them: no "loan", "borrower", "balance" or "due date" in code, UI or issues. The people words slip most: Customer, not "borrower"; Referrer, not "reference"; Primary Number, not "customer ID".008 · 2, 012 · 1, 013 · 2008 · 1
20This repo commits straight to main. Issues drive implementation; `/teach` publishes chapters to main. A local practice branch in chapter 016 is a deliberate training exception, and is deleted when the exercise ends.016 · 1
15A release needs more than a tag. The tag, backend version, frontend version and matching CHANGELOG section must agree; an old patch release must not move Docker Hub’s latest backwards.015 · 2
