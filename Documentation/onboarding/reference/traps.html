Traps: what surprises newcomers

The things in this codebase a new developer is most likely to trip on. Each has one chapter that owns it (explains it fully) and may be warned about earlier. Numbers are fixed, so lessons can say "trap #1". This sheet lists the traps the course has met so far, and grows as chapters are written.

#The trapWarned inOwned by
1Payment write routes live in lending/changes.py, not in payments/. payments/ holds reads, Receipts and the Cash Limit. Every Ledger-changing write, for Mortgages and Payments alike, is in that one module.002 · 2, 006 · 1, 007 · 1003 · 3
2One Payment can be several payment rows. A Final Payment is kept as a part of its own, pointing back through received_with, which the API never shows; the id POST /api/payments returns is the first part.003 · 5, 005 · 3, 007 · 4, 007 · 5007 · 2
3Paying exactly the Outstanding Redeems the Mortgage, in the same request (ADR 0011): record_payment's _redeemed_by compares each Allocation with the quote on its date. A whole Outstanding that can't Redeem is refused, with the rest of the Payment; a rupee less is an ordinary Payment.003 · 2, 003 · 4, 004 · 3, 006 · 2, 007 · 2005 · 3
4Nothing owed is stored. No ledger table, no stored Outstanding, no stored interest-paid. Changing an old Payment changes every later figure, on purpose (ADR 0001).001 · 5, 003 · 4, 005 · 1, 006 · 2, 007 · 1004 · 1
5Previews run the real change and roll it back, so a bug in a change shows up in its Preview too, and a Preview is refused exactly when saving would be. Debug the change function in changes.py, not previews.py. The Preview routes are hand-written on purpose (ADR 0007).003 · 2, 004 · 1, 005 · 3006 · 4
6Units: paise (integers), milligrams, basis points per month, and "out of 30 days" for pro-rata. ₹1,00,000 is Indian digit grouping.002 · 4, 003 · 2, 007 · 1004 · 2
7A month starts before the day's Payments. A month is charged on the Principal at its start; a Payment on an Accrual Date comes after that day's interest and belongs to the new month; today always counts in the Interest to Date. Paying Principal never lowers the month it's paid in (ADR 0006).007 · 5004 · 3
8No scheduler. The daily jobs (Backups, Notices) run on the first /api/ request of the day, from middleware.002 · 5, 003 · 3, 004 · 5010
9Migrations run on every start, after a Backup, with no way back. Unreleased code started on real data migrates it for good.002 · 5010
10API types are generated. Change a backend model, run npm run gen:types, commit openapi.json and api.gen.ts, or tests fail in both languages.002 · 2, 003 · 2, 006 · 5011
12Plain docker compose up runs the published images, not your code. Use docker-compose.dev.yml, with scratch DATA_DIR/BACKUP_DIR on every command.002 · 5014
16Customer-facing text hides internal names. Receipts and Notices use the jewellery's description and the Customer's name, never the Mortgage Name or ids.003 · 5, 005 · 4007 · 5
18backend/tests/ is on the import path, hence api_seed.py rather than http.py, which would hide Python's http.002 · 2013
