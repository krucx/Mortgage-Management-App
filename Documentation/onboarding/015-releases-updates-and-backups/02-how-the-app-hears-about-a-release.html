How the app hears about a release

A release is published. How does the running app find it, and what does the Lender actually do to install it?

By the end you can trace the update status from GitHub's release API to the banner and the Windows Setup link.

The problem

An installed app should tell the Lender about a newer version without checking GitHub on every screen or showing a broken banner while offline. The UI should explain what changed, then let the existing Windows Setup process perform the update.

The idea

The backend checks GitHub at most once per day and compares numeric x.y.z versions. The frontend renders the returned release notes, allows the Lender to put the banner off until a newer release, and on Windows opens the already-registered mortgage-management://update link.

The code

The lock ensures concurrent requests don't all check at once. ASK_EVERY is one day. Version comparison splits each component into an integer, so 3.10.0 is newer than 3.9.0.

The app link invokes Setup; it does not replace the Windows installer flow. The banner then polls /api/update until the backend reports a different running version, and reloads the screens.

Nuance

Predict: A Windows user presses Later on 3.4.1. Will the banner stay hidden after 3.4.2 is released?

It returns. The stored put-off version suppresses the same version or an older one, not a newer release.

Quiz

How often can the backend ask GitHub for the latest release?

ASK_EVERY is one day. Failed lookups quietly result in no available release.
