Chapter 015

Releases, updates and Backups

The problem this part of the app solves

A release has to reach two kinds of installation: Docker pulls an image, while Windows Setup downloads a ready-built zip. A Lender needs to hear that a version is available, understand what changed, and keep the lending book safe while the app changes.

These are connected steps. Publishing the update banner before Docker can pull its image creates a broken offer. Replacing app code is usually reversible; changing the database schema may not be. The Backup taken before that change is the safe route back.

What you'll be able to do

  • Trace a version tag through tests, Docker Hub and GitHub Releases.
  • Explain how the installed app asks about updates and offers Windows Setup.
  • Find the Backup folder, tell what is inside a Backup, and read its status.
  • Describe why a migration failure can require restoring a -before-update Backup.

Before you start

Chapters 014 and earlier explain the Docker image, Windows Setup, app link and migrations. A Backup is a copy of the database and photos that can be used to restore the lending book.
