Developer onboarding

Mortgage Management, for new developers

Mortgage Management is the lending book of a single Lender who lends money against pledged gold jewellery. It runs on the Lender's own laptop and keeps track of who borrowed, against what, how interest grows, what has been paid, and how each pledge ended. This course takes you from never having seen the repo to making your first safe change in it.

How to use the course

  • Read the chapters in order. Each one assumes only the ones before it. A chapter takes about an hour.
  • Each lesson ends with a short quiz, and each chapter with a check-yourself page and a hands-on exercise. Answer before you look: recalling is what makes it stick.
  • Every example uses the same invented sample book, The Gold Chain Story's, on 19 Oct 2026. The cast sheet lists everyone in it.
  • The code is the source of truth. Each chapter records the commit it was written against; if the code has moved on, trust the code, and open an issue about the chapter.
  • Stuck? Ask an agent in this repo to explain anything that's unclear.

The chapters

  1. 001 · What the app does, in plain wordsMortgages, Payments, Closures and the Lender's day, with no code.
  2. 002 · Find your way and run itThe repo's parts, the glossary and ADRs; serve the sample book and run it on scratch data.
  3. 003 · One Payment, end to endFollow Meera's ₹6,600 from form to Preview, API, Ledger and Receipt.
  4. 004 · The Ledger engineHand-trace interest, Capitalisation, Payment order, Term Changes and Projections in ledger.py.
  5. 005 · Replay and ClosuresOutstanding, the quote on a date, Redeem, Waive, Forfeit, Dormant and Reopen in replay.py and changes.py.
  6. 006 · Changes and PreviewsOne door for every change: refuse, write, check_replays, History, and Previews that run the real change and roll it back, in changes.py, previews.py and audit.py.
  7. 007 · Payments and ReceiptsWhat a Payment stores and what it never stores, a Payment in parts through received_with, Voids, the Cash Limit's one sum, and Receipts replayed just after the Payment, in changes.py, payments/ and receipts.py.
  8. 008 · People and CollateralWho a person is (the Primary Number), "new" Referrers and promotion, Customer changes and their 204 Previews, photo files kept in step with the database, and Collateral Value and Loan-to-Value worked by hand.
  9. 009 · Follow-upWho is on the Call List and why, Call Notes one at a time or from a Call Sheet, the Notice queue kept in step by sync rather than a scheduler, a Notice frozen once sent, and messages built from templates and handed to WhatsApp.
  10. 010 · Platform, database and migrationsHow create_app puts the backend together, where "today" comes from, the daily run with no scheduler, settings in config, Tables and paging, and migrations that run on every start, with a -before-update Backup and a drift test.
  11. 011 · The frontend's data layerThe types generated from the backend and the one typed client; reading through one cache, by key; lists a page at a time with the sort in the URL; Previews from a draft, 400 ms after the last key; saving, and what each change makes stale.
  12. 012 · Frontend pages and the PWAThe shell and a read page; a form page wired to its Preview, and a page you build; dividing a Payment and closing Mortgages; the Mortgage page's panels, ID numbers read in the browser and photos saved after the record; follow-up, Settings and the Dashboard; the installed app's service worker, StartGate and UpdateBanner.
  13. 013 · TestingEvery check CI runs, on your machine, and the lint it skips; tests through the API with client and api_seed.py; below it with seed.py, each change on its own date, and pure engine tests; page tests against fakeServer with showPage; and breaking a line to see whether any test pins it.
  14. 014 · How it runs on the Lender's laptopThe one Docker image, run on a copy of the book and debugged; the backend serving the screens without Docker, with the same caching; Setup on Windows read and tested with Pester; each version in its own folder behind the app junction; and the mortgage-management:// link the installed app starts and updates with.
  15. 015 · Releases, updates and BackupsCut a version tag, follow the update banner, make a Backup and restore it if a database migration prevents a rollback.
  16. 016 · Your first changeOne small change, test-first, through every layer. Coming.
