Chapter 016 · Lesson 3

Preview and History

Before saving, the Lender needs to see the effect. Later, History must explain what changed.

By the end: you can add the Preview route and a specific History Action, then prove the tests catch broken behavior.

The problem

A save endpoint alone hides the Ledger impact until after the write. Duplicating its validation in a Preview would let the two paths disagree.

The idea

Call edit_term_change inside the existing rollback Preview helper. Add term_change_edited to the Action vocabulary and one History Change per differing field, including a moved effective date. ADR 0007 keeps Preview routes written out by hand: each route is easy to inspect and uses the same domain function.

Run-through

Ask for the Preview moving Meera's bangles' change from 25 Oct to 25 Nov and setting 1%. Compare the before and after Projection and Ledger. Refresh the Mortgage: the original date and rate remain, because Preview rolled back. Save the edit, then open History and find one row for every changed field.

Run tests/test_previews.py and add a preview-specific test; add History assertions to the API test. For each new behavior, break its implementation line and confirm at least one test fails. This is the mutation check from 013 · Lesson 5.

A test passing on good code is not enough evidence. Count it only after it fails on the broken line.

What does the edit Preview execute?

The Preview helper snapshots, calls the same function and rolls back the transaction.
