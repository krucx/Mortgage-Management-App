Chapter 014 · Lesson 5

The mortgage-management:// link

A web page can't start a program, but the Lender's installed app needs to start the backend, and to run Setup when there's an update. Setup gives it a way: a link Windows knows how to open. This lesson follows that link from a button to a script, and shows why it accepts so little.

By the end you can explain how the installed app starts and updates the app, and why the link is narrow.

The problem

It's Meera Sharma's payment day. The Lender switched the PC on this morning and tapped the Mortgage Management icon, the installed app (PWA) from chapter 012, lesson 6. Without Docker nothing has started the backend: run.ps1 runs only when someone opens the Desktop shortcut. The icon opens the cached screens, and they can't load a single figure.

StartGate notices and says "The app isn't running on this laptop." Telling the Lender to find the Desktop shortcut works, but they've learnt the icon, and "close this, open that" is where people get lost. The page itself should offer Start. But a page in a browser can't run Run.bat; that's the browser's whole security model.

The idea

Register a custom URL scheme for this Windows user. Opening mortgage-management://start runs a small script that starts the app; mortgage-management://update runs Setup. It's the same mechanism as mailto: or zoommtg://: the page opens a link, Windows asks the Lender once whether to allow it, and runs the program registered for the scheme (ADR 0008).

Because any web page can open that link, the script treats it like input from a stranger: it accepts exactly two links and nothing else.

The flow

Notice that there's no reply from link.ps1 to the page. A custom URL scheme is one-way. StartGate doesn't need a reply: the evidence that it worked is the backend answering. After five minutes without one it says to use the Desktop shortcut, whose window shows what went wrong.

The code

Registering the link

  1. An empty URL Protocol value is what marks a registry key as a URL scheme. Set-UserClassValue writes under HKCU\Software\Classes: this Windows user only, so no admin rights are needed (Microsoft: Registering an application to a URI scheme).
  2. Windows replaces %1 with the whole link that was opened, and the quotes make it one argument, whatever it contains. install.ps1 registers it with $Folder = InstallDir\app, so the handler goes through the junction to whichever version runs (lesson 4).

Pester's "registering the mortgage-management:// link" checks both: the URL Protocol value, and that the command ends with -File "…\windows\link.ps1" "%1". "is removed whole" checks that Unregister-AppLink (called by the uninstaller) removes the key and everything under it.

Opening the link

  1. Exactly one argument: "%1". Anything else is not from Windows' registration.
  2. -NoBrowser, because the browser is already open: it's the PWA that asked. StartGate reloads itself once the app answers.
  3. Setup for the newest release, no questions, into this install's folder (Get-InstallDir works from either app\windows or versions\X\windows). Its window stays open only if it fails, so the Lender can read why.
  4. PowerShell's switch runs the block whose label equals the value, and nothing for any other value, $null included.

Line 28 is a regular expression: ^…$ anchors it to the whole string, (start|update) allows only those two words, and /? allows one trailing slash, which some browsers add (mortgage-management://start/). PowerShell's -match is case-insensitive, hence the ToLower(). Nothing after the action is allowed: no ?x=1, no /now, no second argument.

The two buttons

Both show their button only onWindows (navigator.userAgent includes "Windows"), because only Setup on Windows registers the link. On a Mac, StartGate says "The app isn't running. Start its server…", and the banner has no Install now: in Docker the Lender updates with docker compose pull and up -d (the README's "Updating"). How each component waits and reloads is chapter 012, lesson 6.

Nuances

Two gates

Predict: the action is checked twice: by the regex in Select-LinkAction, then by the switch in Open-Link. If a later change loosened the regex so that any word got through, would the app then run anything a web page asked for?

No. mortgage-management://uninstall would pass the regex and return 'uninstall', but the switch has blocks only for 'start' and 'update', so nothing would run. The second gate holds on its own.

But the first gate is what the tests name as the contract: "does nothing for any other action" calls Select-LinkAction directly and expects nothing back. The check-yourself page has you loosen line 28 and see exactly which tests notice, and which don't.

The rest, briefly

  • Why so narrow? Any web page the Lender visits can try window.location = 'mortgage-management://…'. With two fixed actions and no arguments, the worst a hostile page can do is start this app or update it to the newest release, and Windows asks the Lender first. An argument (a folder, a version, a flag) would be a door for whatever a stranger wrote.
  • "%1" is quoted, and checked anyway. The quotes make Windows pass one argument; the count check refuses a handler invoked any other way.
  • Per user, no admin. HKCU is this Windows user's own part of the registry, writeable without elevation. Another user on the same PC has no link.
  • Uninstall removes it whole: Unregister-AppLink deletes the mortgage-management key and everything under it, so no dead link is left pointing at a deleted folder.
  • Rejected: start the app at Windows sign-in, so the icon always just works. ADR 0008 turned it down: the app would always be running in the background, and the update banner would still need a way to run Setup. Also rejected: keeping only the Desktop shortcut, because the Lender already uses the icon, which would then show a page that can't work.

Quiz

Why does Start open a link instead of calling the backend?

Start is shown precisely because nothing answers on the port, so there's no backend to call. A browser page can't run programs, but it can open a link whose scheme Windows has registered, which runs link.ps1. The origin is the backend's own, and there's no such Windows rule.

A web page opens mortgage-management://start?dir=C:\. What happens?

Line 28's pattern ends /?$: one optional slash, then the end. ?dir=… doesn't match, so Select-LinkAction returns nothing and the switch runs nothing. "does nothing when anything more is passed" pins this with start?x=1. Nothing in link.ps1 reads arguments at all.

On the Lender's Mac, the backend is stopped. What does StartGate show?

Only Setup on Windows registers the link, so off Windows StartGate doesn't offer it and says to start the server. It never shows the app without a backend: /api/ is never cached (chapter 012, lesson 6).
