Chapter 014 · Check yourself

Check yourself

Eight questions from across the chapter, in no particular order, then a change to the Windows scripts that you predict before you run it.

Quiz

You changed a screen, then ran docker compose up -d with the scratch folders. Your change isn't there. Why?

Trap #12: docker-compose.yml names krucx11/mortgage-management-app:latest, whichever one you last pulled. Building your code needs -f docker-compose.dev.yml and --build. Compose recreates a container whose configuration changed without down, and the service worker checks sw.js on every load. (Lesson 1)

In a clone with a .env, you run one dev up -d --build without DATA_DIR and BACKUP_DIR. What happens?

Compose fills missing variables from .env, silently. The :? refusal only fires when neither your shell nor .env has a value. On start the app migrates whatever database it's given, with no way back but a Backup (trap #9). (Lesson 1)

Trace it: dist/ holds workbox-051dea9f.js at its top level, not in assets/. Which Cache-Control does the backend send for it?

screens.py line 35 decides by folder, not by name: kept = path.startswith("assets/"). A hashed name outside assets/ is still checked every time, which is harmless, just one extra conditional request. Any file in dist/ is served. (Lesson 2)

Where are the screens' cache headers set, in Docker and without it?

Since ADR 0013 the image sets SCREENS_DIR, so the same serve_screens answers in both modes; nginx and its config are gone (the gap #117 described went with them). vite.config.ts sets the service worker's caching; the backend sets the HTTP headers. (Lesson 2)

Trace it: an update to Y fails at Wait-Version, before Y took any Backup. Where does app point, and what runs?

Set-AppJunction comes after Wait-Version, so it never ran: app still points at X. The catch stops Y and, if Stop-RunningApp said X was running, starts X. With no -before-update Backup found, the message names none. Then setup.ps1 removes Y's folder. (Lesson 4)

What can't a failed update undo, and what does Setup do about it?

Once Y migrates the database, X may refuse it. Setup finds the -before-update Backup and puts its path in the error, leaving the restore to the Lender (ADR 0009). The old version isn't deleted until after a successful switch, and X's .env was never changed. (Lesson 4)

Why does the mortgage-management:// link take two actions and no arguments?

The link is reachable from any page the Lender visits, so it's treated as input from a stranger: at worst, start this app or update it to the newest release, and Windows asks first. Windows passes the whole link as %1, arguments and all; the script refuses them. (Lesson 5)

Why must every file in windows/ be ASCII only?

Trap #14: on the Lender's PC, 5.1 decodes a UTF-8 script without a byte-order mark as the PC's ANSI code page, so a non-ASCII character becomes others and can break a string. Docker's Pester runs PowerShell 7, which reads UTF-8 fine, so it can't catch this. cmp compares bytes, any bytes. (Lesson 3)

Hands-on: loosen the link

You'll change the one line that decides which links link.ps1 accepts, predict what Pester says, and check. You need Docker and chapter 013's mm-pester image (lesson 3 builds it). From the repo root:

  1. Run Pester as it is. 
    docker run --rm -v "$PWD:/repo:ro" -w /repo mm-pester pwsh -NoProfile -c 'Invoke-Pester windows/tests'

    Expect Tests Passed: 65, Failed: 0.

  2. Loosen the regex. In windows/link.ps1 line 28, change (start|update) to (\w+), so the link accepts any word as its action: 
    if ($Arguments[0] -match '^mortgage-management://(\w+)/?$') { return $Matches[1].ToLower() }
  3. Predict, using lesson 5's list of the six link tests: how many fail, which, and why do the others still pass? Write it down.
  4. Run Pester again, with -Output Detailed to see each test.

Check your prediction.

Describing the mortgage-management:// link
  [-] does nothing for any other action 7ms
   Expected $null or empty, but got 'uninstall'.
Tests Passed: 64, Failed: 1, Skipped: 0, Inconclusive: 0, NotRun: 0

From scripts/run_throughs.sh, section 99, at commit 36d403e (on a copy of windows/).

One fails: "does nothing for any other action", at its first line, uninstall. Two surprises in what passes:

  • That same test's start-everything line would still have passed: \w matches letters, digits and _, not -, so start-everything still doesn't match. Pester stops a test at its first failing line, so you only see uninstall.
  • "runs Setup for the newest release on update, and the launcher on start" passes, though it opens mortgage-management://anything. With the loose regex Select-LinkAction returns 'anything', but Open-Link's switch has no block for it, so neither mock is called. That's the second gate, holding.
  • "does nothing when anything more is passed" passes: /?$ still refuses ?x=1 and /now, and the count check refuses two arguments.

So the second gate would have kept this change harmless today, and exactly one test says the contract changed. That's what you want from a test: not that the app broke, but that a promise did.

Recap

  • The app ships as one image, run by Compose with the records in two host folders. Plain Compose runs the published image; the dev file builds yours. Pass scratch DATA_DIR and BACKUP_DIR on every compose command. (Lesson 1)
  • The backend serves the built screens itself when SCREENS_DIR is set, in both modes: pages and sw.js no-cache, assets/ immutable, /api never the app. A stopped backend leaves nothing on the port. (Lesson 2)
  • On Windows, Setup fetches a version's code and runs that version's own install: Docker or local, the .env, uv sync (no Node for a release), the shortcut and the link. Decisions are small functions, pinned by Pester; CI installs, updates and uninstalls for real. Scripts are ASCII. (Lesson 3)
  • Each version has its own folder; app is a junction moved only once the new version answers. A failure starts the old one again. A migrated database can't go back: Setup names the Backup to restore. (Lesson 4)
  • The installed app starts and updates the app through mortgage-management://start and update, registered per user, gated twice, taking nothing else. (Lesson 5)
