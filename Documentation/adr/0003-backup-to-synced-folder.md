# Backups go to a cloud-synced folder, not email

The spec asked for a weekly backup emailed as an attachment. We instead write a password-protected zip (database + photos) to a cloud-synced folder (Google Drive / iCloud) whenever the last backup is 7+ days old, checked on app startup and by the daily run (the first request of each day, since the app may run for weeks without restarting), keeping the last N. A backup is also taken before any database migration. Email breaks past the 25 MB attachment limit once photos accumulate, requires storing an SMTP password, leaves Customer personal data in a mailbox, and "every Sunday" can't be honoured without background processes anyway.

The zip uses the classic zip password (ZipCrypto) so the Lender can open a backup with the tools built into Windows and macOS; that encryption is weak, which we accept for a folder that is already private to the Lender's cloud account. With no `BACKUP_PASSWORD` set the zip is not encrypted at all, and Settings says so.
