# Each change's Preview route is written out by hand beside its save route

Every change to a Mortgage or Payment has a save route and a Preview route, and the Preview runs the real change from the Mortgage changes module and then rolls it back. We keep the Preview routes as short hand-written wrappers rather than declaring each change once and generating both routes from it. Generating them would mean rewriting FastAPI route signatures at import time to save about a hundred lines. Two Previews (a new Mortgage, a Collateral Value) return their own shapes and couldn't share it anyway, and the Void and Reopen Previews take no body while their saves need a reason. The repetition is shallow because the rules live once, in the changes module; what is repeated is only each route's parameters.
