# Strategic vs. Tactical: recheck (27 November 2026)

This rechecks the 21 lines of the [November 2026 strategic-vs-tactical reviews](./README.md)
(PR #499, at `v3.5.2`) on current `main` (`521c389`, `v3.6.1`). Since then the code has had the
refactor run (issues #500 to #511), the bug run (#528), the Call List, Call Sheet and Reminders QA
scenarios (#512 to #514), and the CI overhaul (#566 to #573). Each line below is scored as
**improved**, **unchanged** or **regressed**, with its new rating and the evidence for it. Issue
numbers like #503 are the tickets the commits name. Paths are relative to the repository root.

## Summary

| Area | Before (PR #499) | After (this recheck) | Lines improved / unchanged / regressed |

| Backend | 5 Strategic · 1 Mixed · 0 Tactical | **5 Strategic · 1 Mixed · 0 Tactical** | 2 / 4 / 0 |

- **Four Mixed lines are now Strategic.** Form handling (#511), styling (#502, #506), error handling and
  observability (#500, #501, #509), and cross-cutting concerns (logging and error boundaries).
- **Two lines stay Mixed, though both improved.** Backend state and data flow: the lending and
  payments queries moved into `queries.py` modules (#507), but the People and Reminders SQL is still
  inline, and there are now three ways to open a transaction. Frontend component architecture:
  three of the six named monoliths were split (#503, #504, #505), but `CallListPage`,
  `CloseMortgage` and `NewMortgagePage` are each still over 400 lines.
- **Nothing regressed.** The new risks are size and duplication in CI (`test.yml` is 498 lines with
  20 jobs, and the same path rules are kept in four or five places), plus the new
  `write_transaction` rule that only 6 of about 36 write sites use. Both are candidates in
  [review pass 8](../review-pass-8-2026-11-27/README.md).
