Architecture review, pass 8

Mortgage-Management-App · 27 Nov 2026 · main at 521c389 (3.6.1). This pass comes after the refactor run (#500 to #511), the bug run (#528) and the CI overhaul (#566 to #573). The text version is in README.md in this folder.

The refactor run landed what the strategic-vs-tactical review asked for: one /api router, query modules for Lending and Payments, request logging, /api/health, an error boundary, CSS modules, useNumericId and forms on useProposedChange. The friction left is about where rules live. The Closing draft is built three times. Refusals carry HTTP status codes into the domain. The CI path rules are kept in five lists. And choosing the right write transaction is left to every route.

module seam leak / duplicated rule deep module

Summary: top 5 findings

  1. The Closing draft is written three times (Strong, M). CloseMortgage.tsx, WaiveChosen.tsx and ForfeitChosen.tsx each build a Closing from their own fields. useClosing is deep, but its input is not.
  2. Refusals are HTTP errors all the way down (Strong, M). 30 backend modules raise HTTPException, including replay.py and refusals.py. The fix is a domain Refusal, turned into HTTP once in create_app.
  3. The path rules are kept in five places (Strong, S). Critical areas, CI job groups, changelog needs, the Dependabot allowlist and CONTRIBUTING each keep a list, and the CONTRIBUTING pointer is already wrong.
  4. Choosing a write transaction is every route's job (Worth exploring, S-M). 6 sites use write_transaction and 30 use engine.begin(), though #515 showed read-then-write needs the former.
  5. The page tests' fake backend is untyped (Worth exploring, S-M). fakeServer.ts takes free-string routes and unknown answers, so API drift passes 33 page tests.

  • From the strategic-vs-tactical review: #500, #501, #502, #503 to #505, #506, #507, #508, #509, #510 and #511 are all closed. The recheck is in strategic-vs-tactical-reviews/recheck-2026-11-27.md.

Problem. Each caller keeps its own on, note, method, reference and amount fields, its own ready rule, its own date field name (redeemed_on, waived_on or forfeited_on), its own rupees-to-paise conversion and its own confirmation rows. CloseMortgage is the one-Mortgage case of what the Closures page does for many, yet it shares none of that code, and it sits in components/ although only two pages use it. ClosuresPage and CloseMortgage have 43 touches since October.

Solution. Add a Closing-draft module (useClosingDraft(kind, mortgages), or a draft input to useClosing). It owns the fields, the ready rule, the request bodies and the confirmation rows, so the three callers only render. Move CloseMortgage into pages/mortgage/.

Benefits. Locality: the Closing rules for each kind live in one place. Leverage: three callers today. Tests sit at the draft's interface ("a Waive with no amount gives no Closing"), and the page tests only check rendering.

Problem. The interface of every change function includes FastAPI status codes. Domain tests assert status_code == 422. refusal_names_mortgage changes a framework object's field in place. The newest modules already follow the opposite rule: lending/queries.py says "No HTTP in here".

Solution. Add Refusal(message, kind) to platform/errors.py, with kind unprocessable, conflict or not_found, and one exception handler in create_app. The change is mechanical, file by file, and the API's responses stay the same. ADR 0007 is untouched.

Benefits. Locality: one place maps refusals to HTTP. Leverage: the domain can be used without FastAPI. Domain tests assert on Refusal, and only the route tests see status codes.

Problem. The concurrency rule lives in a docstring, and every route author has to classify their own transaction. Recording a Payment replays the Mortgage and then writes, inside a deferred transaction.

Solution. Make the immediate transaction the only way to write: wrap the engine, or add a test that fails on engine.begin() outside db.py. One parallel-writers test at the seam then covers every route. On a one-Lender SQLite book, queueing writers costs nothing.
